# 0001: 智能体本地优先执行与 Git 提交控制策略 (Local-First Execution & Git Commit Policy)

- **状态 (Status)**: 已接受 (Accepted)
- **日期 (Date)**: 2026-09-22
- **决策人 (Deciders)**: Ateng

## 上下文 (Context)

在 AI Agent 辅助研发过程中，智能体具备直接运行命令行工具（如 `git commit`、`git push`）的能力。然而，若智能体在编写代码或修改配置后，未经开发者人工确认即擅自触发 Git 提交并推送到远程仓库，极易将未经验证、未调整好的中间状态发布至生产或远程 CI/CD 流水线，剥夺了开发者对版本演进的控制权。

## 决策 (Decision)

我们决定在本仓库中确立**本地优先执行（Local-First Execution）原则**：
1. **严禁自动提交**：任何 AI Agent 严禁在未经用户显式、明确许可（如输入“提交到本地”、“推送到远程”）的前提下，擅自执行 `git commit` 或 `git push`。
2. **纯本地修改与自检**：所有代码生成、文档编写与依赖安装默认仅在本地工作区生效。智能体完成修改后，必须在本地通过构建自检（如 `pnpm docs:build`），并将控制权交还给开发者审查。
3. **两阶段显式确认**：本地提交（`git commit`）与远程发布（`git push`）必须解耦，仅在接收到开发者指令时按步执行。

## 影响与权衡 (Consequences)

- **正面收益 (Pros)**：
  - 保障版本库历史干净原子，杜绝半成品与调试废稿污染 Git Log；
  - 避免频繁触发不必要的远程 CI/CD 编译与 GitHub Pages 部署；
  - 赋予开发者充足的本地预览（`pnpm docs:dev` / `pnpm docs:preview`）与审核把关空间。
- **代价与权衡 (Cons)**：
  - 增加了人机交互确认步骤，智能体无法直接进行完全自主的端到端无人值守静默推送（属于符合预期的安全妥协）。
